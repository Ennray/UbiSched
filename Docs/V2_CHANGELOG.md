# 新版整理记录

## 本轮完成

- 增加独立入口 `python -m ubisched`，启动、单次推理、训练和执行端分别有明确子命令。
- 增加共用配置和模型输入约定。训练与在线不再分别维护不同的归一化、评分和采集耗时。
- 保留任务初始能量尺度，避免运行中电量降低时在线特征发生额外缩放。
- 严格检查外部字段、有限数值、取值范围、任务 DAG、归属、正在运行的分配和通信预约。
- 修复 earliest_deadline 在线策略错误映射为未知 edf 名称的问题。
- 规划时使用临时副本检查联合动作，不改变生产端状态。
- 增加 SQLite 持久化协调器，支持方案版本、统一提交、请求去重和事务回滚。
- 增加自动调度循环、资源状态生产端接口、旧评估分值的明确转换、新增任务和新增资源接口。
- 增加传感器与计算资源通用指令、前驱输出引用，以及本机程序 worker。
- 增加开始、完成、失败、取消、超时和显式重试处理。没有反馈时不按估计时长自动完成任务。
- worker 保存启动记录和结果；网络重试不重复启动同一指令。恢复时不确定的执行保留待核对状态。
- 四种模型均可通过同一训练入口保存输入约定，再通过同一推理入口加载。
- 修正旧 C++ 主程序语法和线程 join 问题，关闭下发 socket，释放临时资源对象。
- 旧 C++ 超时回退改为显式配置，避免实验中无提示切回旧算法。
- 增加完整阅读顺序、协议、示例配置和离线回归。

## 没有在本轮开展

没有进行正式多种子性能对比、充分训练、正式消融或规模泛化结论验证。
没有运行 AirSim，没有实测传输时延、能耗或设备控制。
旧框架、旧算法工程及原有实验结果保留，避免丢失对照材料。

## 实际接入还需要什么

真实生产端需要提交任务定义、位置、资源状态和评估结果。旧数字 obs0 不足以恢复这些信息。
实际执行端程序需要按协议完成图像采集、数据读取或传送、计算任务，并报告真实结果。
软件接口和通用进程执行机制已经提供，具体程序仍需要结合用户的 AirSim、识别程序和运行环境完成适配验证。
原包权重仍保留为检查用权重。正式实验应从统一入口训练，再加载带数据约定的新权重。

## 主要阅读入口变更

完整运行入口为 `ubisched/__main__.py`。
原 `structured_bridge.py` 继续负责图状态推理，并保留无状态 UDP 接口。
`iSSROS/main.cpp` 只代表旧 C++ 兼容运行方式，不再作为新版主流程的阅读起点。
